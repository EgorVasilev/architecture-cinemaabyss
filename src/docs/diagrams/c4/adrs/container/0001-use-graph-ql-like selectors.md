# 1. Use GraphQL-like selectors for REST API

## Date
2026-05-21

## Status
Proposed

## Context
1. Требуется поддержка разных видов UI: веб, SmartTV, мобильные устройства
2. Каждый тип UI нуждается в различном наборе данных

Чтобы не перегружать минималистичные форматы UI (например, мобильные устройства), требуется "отфильтровать" ненужные данные в ответе

Стоит выбор между:
    1. Cелекторы в GET-запросах
    2. GraphQL
    3. Client-specific адаптеры

## Decision
Мы решили использовать GraphQL-like селекторы для REST
```
/movie?fields=id,name,title
```

## Consequences
- **Positive:** Можем продолжить использовать REST, сэкономив ресурсы на трудоемки и рискованный переход на GraphQL и трудоемкое создание адаптеров
- **Negative:** 
    - Сложное построение запросов на стороне клиента
- **Neutral:** Потребуется **постепенная** модернизация запросов в клиентском коде
